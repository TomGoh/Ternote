## 1. 项目概述

### 1.1 背景与问题

Notion 未提供满足项目目标的官方 Linux 原生桌面客户端。以 Web/Electron 为核心的方案不适合作为低资源 ARM64 设备上的首选。用户希望像 Obsidian 一样直接管理普通 Markdown 文件，在 Linux x86_64 与 aarch64 上使用轻量级原生编辑器，并通过 Notion 在个人不同设备之间同步。

### 1.2 产品定义 [已确认]

本产品是**本地优先（local-first）的 Linux 原生 Markdown 编辑器，附带 Notion 双向同步能力**，而不是 Notion 完整功能的替代客户端。用户的 `.md` 文件是日常编辑和长期保存的首要数据载体；Notion 是远程交换与访问渠道，不是唯一数据副本。同步冲突应尽可能自动识别并安全处理，无法安全合并时由用户在 Git Diff 风格界面中解决。

### 1.3 目标与成功标准

- G-01 [已确认]：无网络连接仍可完整地创建、阅读、编辑和保存本地 Markdown。
- G-02 [已确认]：应用为真正原生 Linux GUI；不得使用 Electron、CEF 或内嵌 WebView 作为主编辑/渲染引擎。
- G-03 [已确认]：在 Linux x86_64 和 aarch64 可安装运行，优先适配低性能 ARM64 板卡。
- G-04 [已确认]：能将个人笔记在本地与 Notion 之间进行可靠的双向内容交换，并展示同步状态。
- G-05 [已确认]：对检测到的冲突、格式转换风险和失败写入，不得静默牺牲任一已知版本。
- G-06 [建议]：用户可以不启动 GUI，继续通过其他程序访问和编辑 `.md` 文件。

### 1.4 目标用户与主要场景

主要用户为个人知识管理者、开发者及使用资源有限 Linux 设备的用户。典型场景：在 Linux ARM64 上离线写笔记；联网后上传；通过手机或网页端 Notion 编辑；回到 Linux 后拉取并安全合并；在 Neovim 等外部编辑器中修改同一文件。

## 2. 范围与边界

### 2.1 MVP 范围（P0）

1. 本地 Markdown Vault（笔记目录）及文件操作。
2. 原生 Markdown 源码编辑、语法高亮与实时预览（至少支持分栏预览）。
3. 以个人使用为目标的 Notion 身份验证、指定范围的页面绑定/导入/创建。
4. 文本型 Markdown 的安全双向同步；持久化同步基准、失败重试与状态展示。
5. 以三方差异为基础的冲突检测、保留备份、人工决议界面。
6. 对不支持的 Notion Block、截断页面、权限不足与不可转换内容进行风险拦截。

**MVP 同步范围建议**：一个本地 Vault 对应一个 Notion 根页面；先支持根页面下的普通笔记页面。嵌套多层目录、复杂数据库及跨工作区同步为 P1/待决，不应阻碍单层多笔记的 MVP。该范围尚未由产品负责人确认。

### 2.2 延后到 P1

单栏所见即所得式 Live Preview、递归目录/子页面树、复杂 Notion Block 编辑、图片/附件双向迁移、全文搜索及 FTS 索引、独立同步 CLI、Git 历史集成、跨 Vault、多账户、移动端客户端、可插拔其他同步后端。

### 2.3 明确非目标（OUT）

多人在线协同、CRDT/OT、多人光标、Notion 全量数据库视图/自动化/AI 功能复刻、官方 Notion 同步协议逆向、服务端托管服务、跨平台 GUI（Windows/macOS）的首版支持。

## 3. 术语与优先级

- **Vault**：用户指定的本地 Markdown 根目录。
- **Local**：当前 `.md` 文件内容；可以在应用外修改。
- **Remote**：最近一次从 Notion API 成功读取的页面内容。
- **Base**：上次经验证同步完成的共同语义版本与关联元数据，用于三方比较。
- **冲突**：Local 与 Remote 相比 Base 都发生了无法自动安全整合的变化；格式不可判定也可能导致阻塞，而非普通文本冲突。
- **格式适配层**：通用 Markdown 与 Notion-flavored Markdown v2 之间的转换与兼容性判定。
- **语义等价**：允许无害的 Markdown 规范化（如等价列表标记），但不得丢失正文内容或结构含义。
- **P0/P1/OUT**：MVP 必需/后续版本/明确不支持。

## 5. 数据规则与同步状态机

### 5.1 数据所有权与不变量

1. INV-01：`.md` 文件是本地编辑和长期保存的主要数据载体；Notion 可返回远程更新，但不能无条件覆盖本地未确认变更。
2. INV-02：Base 是**共同同步基准**，不是“本地版本永远赢”的优先级标记。
3. INV-03：所有发生过的、已识别的冲突版本，在用户明确丢弃之前必须可以恢复。
4. INV-04：格式无法安全转换、权限不足、远端内容截断时，以阻塞写入优先于“尽量同步”。
5. INV-05：页面标题、路径、Notion ID、同步状态和正文分开建模；文件路径可变，远端 Page ID 不可凭路径推断。
6. INV-06：不默认传播删除；尤其不自动将本地缺文件映射为远端页面删除。
7. INV-07：远端 API 不提供本项目所需的已验证原子版本比较与提交保证，故不得声称跨端强一致或零竞争窗口；采用事前重读、保留快照、事后校验及冲突提示降低风险。

### 5.2 建议状态（待设计细化）

`UNBOUND` → `SYNCED`；内容变化进入 `LOCAL_DIRTY`、`REMOTE_DIRTY` 或 `BOTH_DIRTY`；执行进入 `SYNCING`；无法自动处理进入 `CONFLICT`；不完整数据/权限/格式问题进入 `BLOCKED`；网络故障进入 `RETRY_PENDING`；写入结果不确定进入 `VERIFY_REQUIRED`。网络离线是环境条件，不能替代文档的脏状态。

### 5.3 核心同步决策表

| Local vs Base | Remote vs Base | 处理 |
| --- | --- | --- |
| 相同 | 相同 | 保持 `SYNCED` |
| 不同 | 相同 | 执行安全上传与回读验证 |
| 相同 | 不同 | 备份本地后导入远端，更新 Base |
| 不同 | 不同且可证明安全合并 | 生成合并候选、复核后提交 |
| 不同 | 不同且重叠/不确定 | 停止提交，进入冲突界面 |
| 任意 | 远端不可完整读取/转换 | 阻塞自动写入并显示原因 |

### 5.4 单篇同步事务要求

- `S1` 固化当前本地文件快照，查询远端并保存检查时的远端快照及元数据。
- `S2` 验证格式转换、页面权限、截断标记、媒体引用、页内特殊结构及同步映射。
- `S3` 基于 Base 比较并选择无操作、拉取、候选合并、上传或阻塞；有冲突不自动写入。
- `S4` 写入前再次核对远端状态；优先使用有边界的定点修改，禁止默认进行整页破坏性覆盖。这里属于实施策略，PoC 需验证可行性。
- `S5` 检查 API 结果和 warnings，回读并做语义级校验；失败、不确定或异步未结束不得更新 Base。
- `S6` 仅在成功且当前 Local 仍等于提交版本时持久化新的 Base；否则继续保留待同步状态并重新比较。

**重要限制**：Notion 公开 API 的 Markdown 更新不是通用 Git push，也不能假设具有客户端可用的 CAS（Compare-and-swap）事务。最后一次远端检查与写入间仍存在竞争窗口。系统必须将其作为已知一致性限制记录到风险及用户说明中。

### 5.5 数据及元数据（逻辑模型，非物理设计）

每个绑定条目至少需要：`local_document_id`、相对路径、`notion_page_id`、`base_content_snapshot`、`base_semantic_hash`、最后观测远端元数据、`local_hash`、同步状态、最近成功时间、待处理操作与错误、冲突/恢复快照引用。机密令牌不写入普通 Vault 文件。

| AT-005 | 两端修改同一段文字 | 禁止自动覆盖；界面显示三方差异；用户可手工决议 | FR-050~053 |
| AT-006 | 两端修改不相交段落 | 若算法可安全合并则同步；否则保守进入待决状态，无内容丢失 | FR-030, FR-050 |
| AT-007 | 远端存在 `<unknown>`、截断或未支持的 Notion 块 | 停止危险写入；保留本地文件；显示原因 | FR-035, FR-039 |
| AT-008 | 上传请求超时或返回成功但含 warnings | 不提前更新 Base；核查远端内容；必要时人工处理 | FR-032, FR-036, FR-054 |
| AT-009 | 同步期间网络断开并重启应用 | 本地文件不受影响；任务为待重试/待核验，不假报成功 | FR-033, FR-054 |
| AT-010 | 外部编辑器同时修改已打开的文件 | 检测外部变化；避免无提示覆盖一方内容 | FR-004 |
| AT-011 | 本地删除已绑定文件，远端页面仍在 | 不自动删除远端；标记待处理并提供恢复/解绑选项 | FR-007, INV-06 |
| AT-012 | 凭据过期或远端撤销访问 | 本地编辑正常；该笔记同步受阻并明确提示授权问题 | FR-024, FR-055 |
| AT-013 | 在 ARM64 和 x86_64 分别运行验收集 | 均满足平台、原生性及校准后的响应/内存目标 | NFR-001~005 |

**MVP 放行条件**：所有 P0 需求有对应测试并通过；AT-001 至 AT-013 的适用场景通过；不得存在已知可导致已保存本地正文不可恢复的 P0 缺陷。性能及兼容格式的验收样本集在 PoC 后冻结。

## 8. 技术约束与待验证假设

### 8.1 已核实的外部 API 能力（截至 2026-11-03）

- Notion 提供 `GET /v1/pages/{page_id}/markdown`、`PATCH /v1/pages/{page_id}/markdown`，并支持创建带 Markdown 内容的页面；建议显式指定 `markdown_version: v2`。
- Notion-flavored Markdown v2 与普通 Markdown 有差异，包括扩展标签、特殊块、媒体、子页面等；部分 Block 会表现为 `<unknown>`。
- API 返回 `truncated`、`unknown_block_ids` 等字段；更新返回的 `warnings` 可能表示内容被修改/忽略或部分搜索替换未命中。
- 默认删除子页面/数据库的危险操作受到 API 保护；不能将此机制当作对其他普通内容的完整数据保护。
- 公开 API 存在连接级与 Workspace 级请求限流，需处理 `429`、`529` 和 `Retry-After`。
- 可以使用个人访问令牌（PAT）作为个人使用模式的候选认证方式；公开分发的授权方案仍待决。

### 8.2 强制 PoC 项目（先于架构冻结）

| ID | 验证问题 | 通过标准 |
| --- | --- | --- |
| POC-01 | 标准 Markdown ↔ Notion v2 往返 | 对冻结的核心语法语料，语义无损；不可无损场景能被明确识别并阻塞回写。 |
| POC-02 | 同步竞争与异常 | 用双客户端修改、超时、HTTP 429/529、异步更新模拟，验证 Base 不会错误推进。 |
| POC-03 | 未知块与子页面保护 | 构造 `<unknown>`、权限缺失、截断、子页面，验证无静默丢失。 |
| POC-04 | ARM64 GUI 性能 | 在指定真实低性能 ARM 板卡上测量启动、输入、预览、滚动和 RSS，决定 GTK4/Qt/Slint 等候选框架。 |
| POC-05 | 凭据存储 | 验证无桌面密钥环的发行环境能安全完成连接与断开。 |

## 9. 主要风险与应对

| 风险 | 等级 | 初步控制 |
| --- | --- | --- |
| Markdown 方言转换丢失块/属性 | 高 | 可逆子集、语义校验、未知块只读、禁止自动整页覆盖 |
| 两端同时写入且 API 缺少可证明原子 CAS | 高 | 三方比较、提交前重读、回读、快照、冲突 UI；披露剩余竞争窗口 |
| ARM64 低端设备 GTK/渲染性能不足 | 中高 | 真实硬件 PoC，允许换 GUI 框架，不先冻结 GTK4 |
| API 限流、超时和大文档限制 | 中 | 队列、退避、分页/大小保护、状态可恢复 |
| 凭据暴露、远端内容恶意链接 | 高 | 最小权限、凭据隔离、禁止执行远端内容、输入验证 |
| 公开发布的 API 条款/商标边界 | 中高 | 发布前合规核对；个人研究版与公开分发版分开评估 |
